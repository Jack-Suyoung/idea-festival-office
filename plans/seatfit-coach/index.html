    1. 한 줄 요약¶

    • 4개월 동안 만들 것: 손에 들리는 200g 휴대형 박스 1대 + 카시트 5종 모델 DB + 5초 거치 자가 점검 시연(등받이 각도 / ISOFIX 인디케이터 / 하네스 위치 / pinch test 정량) → 30개 시나리오 시연 영상.
    • 핵심 데모 메시지: NHTSA 46% 카시트 오장착이 이 박스로 5초만에 사라진다 — 폰 앱이 못 하는 것을 ToF + 로드셀 + IR 링이 한다.

    2. 16주 마일스톤¶

    단계 주차 주요 작업 나가는 산출물 통과 기준 (게이트)
    M1 PoC W1 BOM 발주(국내 1일~3일 / 알리·디지키 7~14일), 카시트 1호기(다이치 또는 페도라) 확보 발주 리스트, 카시트 1대 모든 부품 W2까지 입수
    W2 RPi5 부팅·OS·OpenCV/PyTorch, ToF VL53L5CX I2C 동작 확인, 광각 카메라 캡처, IMU(BNO055) 자세 출력, HX711 로드셀 raw 값 출력 5개 센서 단독 동작 영상 각 센서 raw 데이터 시리얼 출력
    W3 박스 케이싱 v1 3D 프린팅(3회 이터레이션), 18650 + 5V 부스트 전원, 손잡이 그립, 센서 마운트 케이싱 v1 (200g 미만 목표) 박스 휴대 가능 + 5분 이상 배터리 동작
    W4 M1 게이트: 박스 거치 → ToF로 카시트 등받이 각도 측정 (30~60° 범위, ±2° 오차 검증) M1 데모 영상 (1분) 각도 측정 ±2° 이내, 5초 내 결과 표시
    M2 알고리즘+HW 통합 W5 카시트 5종 라벨 사진 수집 (다이치·페도라·브라이택스·맥시코시·사이벡스) — 본인이 카시트 매장 방문 + 온라인 이미지 200장 라벨링. PaddleOCR 또는 TrOCR fine-tuning. 모델·만료일·시리얼 OCR 카시트 모델 OCR 모델 v1 + 5종 가이드 JSON DB (배우자 작성) OCR top-1 정확도 ≥90% (5종)
    W6 광각 카메라 + IR LED 링으로 ISOFIX 인디케이터 색(녹/적) 분류 + 하네스 어깨 슬롯 위치 인식 (YOLOv8-nano fine-tune, 데이터 100장) 인디케이터/하네스 위치 분류기 정확도 ≥85% (테스트 30장)
    W7 2축 로드셀 + 슬림 프로브로 pinch test 캘리브레이션 (배우자가 임상 적정 장력 0.5~1.5N 정의 → 캘리브레이션 곡선) pinch test 모듈 + 캘리브레이션 표 동일 장력 10회 측정 표준편차 ≤0.1N
    W8 M2 게이트: 5개 센서 결과를 RPi5에서 통합 → LED 매트릭스 8×8에 항목별 OK/경고 + 1W 스피커 음성 가이드 출력 (TTS pre-rendered wav) 통합 데모 v1 (연구실, 카시트 1대) 5초 거치 → 4개 항목 진단 결과 출력 성공
    M3 시나리오 통합 W9 카시트 5종 모두로 OCR + 진단 회귀 테스트, 실패 케이스 데이터 추가 학습 5종 카시트 진단 결과표 5종 모두 4개 항목 진단 성공률 ≥80%
    W10 박스 케이싱 v2 (마감·라벨·로고), 손잡이 UX 개선, 1버튼 시작, 부팅 시간 단축 (RPi5 systemd 최적화 → 콜드 스타트 15초 → 5초) 케이싱 v2 + 부팅 5초 이내 부팅~진단 완료 10초 이내
    W11 클라우드 백엔드(AWS Lambda + DynamoDB, 또는 단순 GitHub Pages JSON) — 카시트 모델 매칭 시 가이드·만료일·리콜 정보 fetch (오프라인 캐시 fallback) 백엔드 v1 + 박스에서 매칭 데모 5종 카시트 매칭 + 오프라인 fallback 동작
    W12 M3 게이트: 30개 시나리오 시연(영유아/토들러 × 정상/오장착 × 5종 카시트). 배우자가 사용성(SUS) 5명 테스트 (지인 부모) 통합 데모 v2 + SUS 점수 30개 시나리오 중 25개 이상 정상 진단 + SUS ≥70
    M4 데모+발표 W13 시연 영상 촬영 (다각도, 4K) — 정상 장착 5종 / 오장착 시나리오 5개 / 박스 휴대·거치·결과 출력 클로즈업. 마네킹 인형 2종 (영유아 5kg / 토들러 12kg) 풀 시연 영상 (raw) 모든 시나리오 1회 이상 성공 컷 확보
    W14 발표 슬라이드 작성 (5분 분량 12장), 데모 영상 컷 편집 (3분 fallback 영상 포함) 슬라이드 v1 + 편집 영상 v1 슬라이드 5분 안에 끝남
    W15 리허설 ×3 (배우자 + 페르소나 부모 1명 청중), 시연 실패 fallback 영상 검증, Q&A 예상 답변 (critic 4개 포인트) 카드 작성 리허설 영상 + Q&A 카드 5분 ±15초 + Q&A 답변 4건 모두 준비
    W16 M4 게이트: 최종 다듬기 + 백업 박스(혹시 모를 고장 대비 박스 구성품 예비 1세트) + 발표장 환경 점검 (조명·소음·Wi-Fi off) 최종 데모 패키지 본선 5분 발표 + 시연 영상 fallback 준비 완료

    4. HW/SW 분담 (시간 배분)¶

    가용 시간¶

    • 본인 (엔지니어링 1인): 평일 저녁 2h × 5일 + 주말 7h × 2일 = 주 24h (보수적으로 주 18h로 잡고 = 16주 × 18h ≈ 288 man-hour)
    • 배우자 (간호사·자문): 주 4~6h (본업 외, 임상 룰베이스·만료일 가이드·사용성 테스트·발표 임상 답변 카드만) = 약 80 man-hour, 코드 0
    • 페르소나(본인=두 아이 부모): 필드 검증은 본인이 동시에 수행. 추가로 SUS 5명 테스트는 W12에 지인 부모 5명 (각 30분) 모집.

    본인 288h 배분¶

    영역 시간 비중 주요 항목
    SW (비전 AI / 센서 퓨전 / 통합) 150h 52% 카시트 모델 OCR fine-tuning(40h), ISOFIX/하네스 분류기(25h), 다센서 퓨전·각도 알고리즘(30h), 클라우드 매칭(15h), LED/스피커 UX(15h), 회귀 테스트(25h)
    HW (케이싱 / 배선 / 결합) 80h 28% 케이싱 v1·v2 3D 프린팅 + 이터레이션(30h), 전원·배터리(15h), 센서 마운트·캘리브레이션 지그(20h), pinch 프로브 가공(15h)
    데모 준비 (영상·슬라이드·리허설) 58h 20% 30개 시나리오 촬영(20h), 편집(15h), 슬라이드(10h), 리허설(8h), Q&A 카드(5h)

    배우자 80h 배분¶

    • 카시트 5종 임상 가이드 JSON 작성 (영유아 45° / 토들러 30~45° / 하네스 어깨 슬롯 / 체스트 클립 위치): 25h
    • pinch test 임상 적정 장력 정의(0.5~1.5N) + 캘리브레이션 검토: 10h
    • 30개 시나리오 임상 적정성 검토 + SUS 5명 테스트 진행: 25h
    • 발표 임상 답변 카드(Q&A) + 본선 발표 시 1분 임상 코멘트 영상 녹화: 20h

    4개월 가능성: 타이트 (가능)¶

    근거: - M1 게이트(W4 ToF 각도 ±2°)와 M2 게이트(W8 통합 데모 v1)가 합리적이고 본인의 자율주행 SW 코어 자산(센서 캘리브레이션·각도 추정)과 직접 일치. - 가장 타이트한 구간은 W5~W8 (M2): 카시트 5종 OCR 데이터 수집·라벨링 + 인디케이터 분류기 + pinch 캘리브레이션이 4주 안에 동시 진행. → 데이터 수집은 W1~W4와 병행 가능(부품 발주 리드타임 동안 카시트 매장 방문·온라인 이미지 라벨링 시작).

    위험 시 축소판¶

    • 5종 → 3종: 다이치·페도라·브라이택스 3종으로 축소(한국 점유율 상위). 시연·OCR 데이터 부담 40% 감소.
    • 클라우드 백엔드 → 정적 JSON: AWS 대신 RPi 내장 JSON으로 fallback. 데모 시 차이 없음.
    • 30개 시나리오 → 15개: 영유아/토들러 × 정상/오장착 × 카시트 3종 = 12개로 축소. 단, 영상 fallback은 30개 다 찍어 두기.

    5. 리스크 & 대응¶

    # 리스크 시점 영향 대응 백업 플랜
    1 부품 수급 — VL53L5CX 또는 광각 USB 카메라 알리 배송 14일 + 통관 지연 M1 (W1-3) 상 W1 즉시 발주 + 국내 디바이스마트 우회 동시 발주 VL53L5CX → VL53L1X(단일 zone) 2개로 대체 가능. 광각 카메라 → 라즈베리 카메라 V3 광각으로 대체
    2 카시트 모델 DB 지속성 (critic 핵심 공격 포인트 #2) — 4개월에 5종은 가능하나 한국 시장 100+ 모델 확장 비용 M2 (W5-8) 상 (a) 5종을 한국 점유율 80% 커버하도록 선정(다이치·페도라·브라이택스·맥시코시·사이벡스) (b) OCR 신뢰도 임계값 + 미인식 시 사용자에게 모델 수동 선택 폴백 UX 구현 → "DB 부재 = 진단 불가"가 아니라 "DB 부재 = 매뉴얼 모드"로 전환 (c) 양산 단계 OEM 협업 로드맵을 발표에 명시 5종 안 되면 3종으로 축소. 매뉴얼 모드는 어쨌든 ToF 각도/로드셀 장력은 모델 무관하게 측정 가능 → 부분 진단으로도 가치
    3 "폰 앱 + 외장 BLE로 안 되나" (critic 핵심 공격 포인트 #1) M2 (W5-8) + M4 발표 상 (a) BOM #21 외장 BLE 텐션 게이지 1대 구입해 사이드바이사이드 비교 영상 촬영 — "폰 앱 + 외장 BLE 게이지 조합 vs SeatFit Coach 1박스" 진단 시간/정확도/UX 비교 (b) 발표에서 "폰에 ToF 4×4 zone 없음 / 폰에 IR 링 없음 / 폰 카메라는 카시트 옆에 거치 어려움 / 다 풀면 부모가 도구 3개 들고 있음" 4점 한 슬라이드 비교 시연 안 되면 정량 표로 대체(센서 사양 비교)
    4 비전 AI 일반화 부족 — OCR이 학습 5종에선 동작하나 같은 모델 다른 라벨 위치/조명 실패 M2-M3 (W6-W11) 중 데이터 augmentation(조명·각도·블러), IR 링 광원 균질화, 신뢰도 임계값 + 매뉴얼 폴백 시연용 카시트는 라벨 깨끗한 신품 사용. 영상 촬영 시 OCR 실패 컷은 cut
    5 다양한 차량 좌석 환경 — 시연을 차량에 한 적이 없음. 카시트 단독 시연으로 충분한가 M3 (W12) 중 본인 차량 (카시트 두 아이 부모) + 배우자 차량 + 지인 차량 1대 = 3대에서 W11~W12 실측. ISOFIX 환경 차이 데이터 확보 차량 못 구하면 카시트만 룸에 두고 시연 — 핵심은 카시트 표면 측정이므로 차량 의존 0
    6 사용자 마찰 — 5초 거치 UX가 실제로 5초 안 끝남. 부팅 + 측정 합쳐 30초 이상 가능 M3 (W10) 중 RPi5 systemd 최적화로 콜드 스타트 15초 → 5초. 또는 상시 슬립 모드 + 시작 버튼으로 즉시 측정 구현. ESP32-S3 보조 MCU가 LED·1차 응답 즉시 처리, RPi5는 백그라운드에서 OCR 부팅 5초 안 되면 "전원 항상 ON, 1버튼만" UX로 시연
    7 3D 프린팅 케이싱 이터레이션 지연 M1-M2 중 W3에 v1 출력 시작 (이터레이션 3회 가정 W3·W6·W10), 외주 출력(Cubicon3D, 큐비콘 등) fallback 예산 5만원 추가 확보 외주 시 +3일 지연 흡수
    8 가족·본업 충돌 — 본업 자율주행 SW + 두 아이 양육 + 16주 작업. 배우자도 야간 근무 변동 전 기간 중 (a) 주 18h를 기준으로 잡되 W4·W8·W12 게이트 후 1주 완충 주차에 가족 시간 확보 (b) 배우자 작업은 비동기(임상 JSON·SUS) — 야간 근무 시기에 의존 안 함 (c) 본업 자율주행 객체 탐지 코드 자산 재사용 → 처음부터 짜지 않음 게이트 기준 미달 시 "축소판" 트리거 (5종 → 3종 / 클라우드 → 정적 JSON / 30 시나리오 → 15)
    9 시연 실패 (라이브) M4 (W16 본선) 상 사전 녹화 영상 풀버전 (3분) + 30개 시나리오 영상 인덱스 항상 노트북에 + USB에 백업. 라이브 실패 시 발표자가 "이 케이스는 영상으로 보여드리겠습니다" 자연스러운 fallback 영상도 안 되면 슬라이드의 정량 데이터 표로 대체(SUS·진단 정확도·시간)

    8. critic 방어 포인트 (1차 평가 약점 답변)¶

    평가에서 critic이 공격할 4개 포인트(reports/evaluations/seatfit-coach.md L60~63)를 plan에 어떻게 미리 반영했는지:

    공격 #1 "왜 휴대형 박스인가, 폰 + 외장 BLE로 안 되나" — 가장 강한 공격. 방어: ① BOM #21에 시중 외장 BLE 텐션 게이지 1대를 구입해 W12 통합 데모 v2에서 사이드바이사이드 비교 영상(폰 앱 + 외장 BLE 게이지 vs SeatFit 1박스) 촬영. 진단 시간/정확도/도구 개수/UX 4축 비교. ② 발표 1:30~2:00 슬롯에 이 비교를 한 슬라이드로 직격. ③ 정량 근거: 폰엔 ToF 4×4 zone(VL53L5CX), IR 940nm 링 광원, 2축 로드셀이 모두 없음 + 폰을 카시트 옆에 정확히 5초 거치하는 UX 자체가 부모에겐 어려움.

    공격 #2 "카시트 모델 DB 지속성" — 방어: ① 4개월 PoC 5종은 한국 점유율 80% 커버(다이치·페도라·브라이택스·맥시코시·사이벡스)로 의도 선택. ② OCR 신뢰도 임계값 + 매뉴얼 폴백 UX 구현 — DB 미인식이어도 ToF 각도·로드셀 장력은 모델 무관하게 측정 가능 → 부분 진단으로 사용 지속. ③ 양산 로드맵에서 "1단계 애프터마켓 출시(다이치·페도라 OEM 협업) → 2단계 카시트 OEM 자체 SDK 등록 (만료일·리콜 정보 OEM 측이 PUSH)"로 OEM 협업 인센티브를 명시.

    공격 #3 "부모 자비 구매 의향 + OEM 동봉 인센티브" — 방어: ① 양산 경로를 자비 단독 구매에 의존하지 않도록 다층화: (a) 현대차·기아 신차 동봉 (Palisade·Carnival·Sorento·Telluride 패밀리 SUV) = 차량 OEM이 카시트 OEM과 무관하게 "자기 신차에 어떤 카시트든 안전 점검할 수 있는 도구"를 동봉 → 차량 OEM 인센티브: 패밀리 SUV 안전 마케팅 차별화 + 영유아 가족 NPS 상승 (b) H-Genuine Accessory (애프터마켓) (c) 보건복지부·서울시 영유아 안전 지원 사업 ② 발표 4:00~5:00 슬롯에 "1→2→3 단계 양산 로드맵" 한 슬라이드로 정리.

    공격 #4 "자율주행 SW 강점 활용 약함" — 방어: ① 본 plan에서 본인의 자율주행 코어 자산을 직접 매핑: ToF 4×4 zone + IMU + 광각 카메라 다축 센서 퓨전 = 자율주행 LiDAR + IMU + 카메라 퓨전 파이프라인의 축소판 / 카시트 라벨 OCR = ADAS 표지판/차선 OCR 자산 / 카메라 캘리브레이션 = ADAS 카메라 캘리브레이션 자산. ② 발표 4:00~5:00에 "팀 강점이 후보의 핵심 기술과 직접 일치"를 1줄로. ③ M2(W5~W8) 가장 큰 시간(150h SW 중 70h)을 다센서 퓨전과 OCR에 배분 → 자산 재활용이 일정 단축의 근거.
