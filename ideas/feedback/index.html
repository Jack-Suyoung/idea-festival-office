    사용자 피드백 (idea_generator 입력)¶

    이 파일은 idea_generator 가 매 배치 시작 시 반드시 읽어 발산 정책에 반영해야 한다. 사용자가 직접 추가/수정한다. 신규 항목은 위쪽에 추가하는 시간 역순.

    제외 메커니즘 (절대 재발산 금지)¶

    1. 차량 자체 실내 측위 (Pillar OCR + IMU + 기압)¶

    • 추가 일자: 2026-05-10
    • 사유: OEM 양산 기능으로 확인됨. 사용자가 이미 검토 완료.
    • 재발산 금지 키워드: "스마트 위치 허브 박스", "Pillar OCR", "주차장 기둥 번호 인식", "차량 자체 실내 위치 추적", "인프라 독립 실내 측위" 등 동일 카테고리.
    • 차별 각도로 살리려는 시도도 금지 — 이 카테고리 자체에서 손을 뗀다.

    사용자 제작 역량 한계 (Hard Constraint)¶

    차량 시스템 직접 연동 불가¶

    • 추가 일자: 2026-05-10
    • 불가능한 것:
    • HVAC ECU 메시지 송수신 (좌/우 카시트 영역별 풍량·온도 제어 등)
    • 엔진/조향/브레이크 ECU 직접 연동
    • AVN/E-GMP 양산 통합
    • 사내 R&D 차량의 BSD/AVM/라이다 raw 데이터 접근
    • 사유: 사용자에게 해당 차량·장비가 없음. 회사 내 R&D 자원 사용 가능 가정도 하지 말 것.
    • 권장 패턴: 차량 외부에 부착·거치·탑재되어 차량 ECU에 의존하지 않고 자체 동작하는 액세서리/박스/모듈 형태. 차량 환경은 목업/모형/마네킹으로 시뮬레이션.

    가능한 메이커 부품 (참고)¶

    • 임베디드: Jetson, Raspberry Pi, Coral, ESP32, Arduino
    • 센서: USB/IR 카메라, ToF, UWB, IMU, 마이크 어레이, 압력 매트
    • 액추에이터: 12V 팬, 스테퍼/서보, LED 매트릭스, 소형 디스플레이, 진동 모터
    • 통신: BLE/Wi-Fi, 스마트폰 앱
    • 메커니컬: 카시트/좌석 목업, 마네킹, 3D 프린팅 케이싱

    발산 시 우선 적용할 방향성¶

    좋아한 아이디어 (DNA를 더 살릴 것)¶

    • SafeAlight (#2 of batch1) — 어린이 하차 안전. 양산 가능성·의미·니즈 모두 탁월.
    • 단, 현재 형태는 SW-only 라 Maker's Track 부적합. HW 제작 요소를 추가하여 develop 필요.
    • HW 보강 방향(idea_generator 참고): 도어 핸들 LED 모듈 자체 제작 / 외부 경고 라이트·부저 모듈 / 카시트 압력 센서 패드 / 어린이 도어 잠금 솔레노이드 액추에이터 / 외부 부착형 레이더+카메라 통합 박스 등 — 차량 ECU 연동 없이 차량 외부에 부착되는 독립 박스/모듈로 재설계.

    부분적으로 좋은 아이디어 (보강해서 다시)¶

    • BabyVision Guardian (#1 of batch1) — 카시트 비전 AI 생체 모니터.
    • HVAC 연동 부분은 사용자 제작 역량 한계로 제거.
    • 비전 AI 생체 모니터링(rPPG, 호흡, 자세) 자체는 살릴 수 있음. 출력은 HVAC 제어가 아닌 자체 알림/표시 HW(예: 부모 스마트폰 푸시, 운전석 후방 미니 디스플레이, 차량 외부 거치형 LED 패널, 진동 알림 손목 밴드 등)로 재구성.

    작성 가이드 (사용자가 추가할 때)¶

    • 제외: 발산하지 말 메커니즘과 사유.
    • 제작 역량 한계: 사용자가 만들 수 없는 환경/장비 조건.
    • 방향성: 좋아한/부분적으로 좋은 아이디어와 보강 방향.
    • 항목은 시간 역순으로 위쪽에 추가. 오래된 항목도 유효하면 그대로 둠.
